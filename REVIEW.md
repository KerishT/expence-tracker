# Code Review

Правила ревью для Expense Tracker. Ревьюер проверяет соответствие этим пунктам перед approve.

## Когда и как ревьюим

- Ревью проходит **каждый PR** в `main` (GitHub Flow: ветка → PR → review → merge → удалить ветку).
- Нельзя апрувить собственный PR без причины; для важных изменений — хотя бы один сторонний review.
- Автоматический проход — workflow `claude-code-review.yml` (запускается на `opened/synchronize/ready_for_review/reopened`). Его замечания разбираем наравне с ручными.
- Ревьюер начинает с `git diff main...HEAD --stat`, читает **Summary** и **Test plan** из тела PR и сверяет, что описание соответствует диффу.

## Что обязательно проверить (cross-cutting)

- **Заголовок и коммиты** — Conventional Commits: `<type>(<scope>): <subject>`, lowercase, imperative, без точки. Типы: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`.
- **Тело PR** содержит **Summary** (что реализовано, затронутые endpoints/модули) и **Test plan** (ручные шаги проверки).
- **Границы слоёв соблюдены** — фронт не лезет в код бэка и наоборот; общее идёт через API-контракт `/api/*`.
- **Линт/типы зелёные**: `npm run lint` (все workspaces). Для фронта — `npx tsc --noEmit` (в Next.js 16 `next lint` отсутствует). Бэк — `eslint src/**/*.ts`.
- **Форматирование**: `npm run format` (Prettier) не оставляет диффа.
- **Нет мусора в дифе**: закоммиченные `dist/`, `.next/`, `.env`, секреты, `console.log`/отладка, закомментированный код.
- **Секреты только через env** (`DATABASE_URL`, `JWT_SECRET`, `JWT_EXPIRES_IN`); новые переменные добавлены в `backend/.env.example`.
- **Изменение схемы данных** сопровождается миграцией Prisma (`prisma/migrations/`), а не правкой только `schema.prisma`.
- **Документация актуальна**: новые конвенции/команды отражены в соответствующем `CLAUDE.md` (root / frontend / backend).

## Backend (NestJS + Prisma + CQRS)

- **Скоупинг по пользователю**: любой доступ к данным (кроме `/auth/*`) фильтруется по `req.user.id`. Проверить, что чужие записи недоступны.
- **JWT-защита**: непубличные роуты под `@UseGuards(JwtAuthGuard)`; текущий юзер берётся из `req.user`, не из тела/квери запроса.
- **Границы модулей через CQRS**: модуль не ходит в чужие таблицы Prisma напрямую — только через `CommandBus`/`QueryBus` (напр. `GetUserByIdQuery`, `GetCategoryByIdQuery`). Со своей таблицей — Prisma напрямую допустимо.
- **Структура модуля**: `controller` / `service` / `module`, входные `dto/` (class-validator), доменные `domain/*.dto.ts`, мутации в `commands/`, чтение в `queries/`.
- **Наружу отдаётся domain DTO**, а не Prisma-модель — маппинг в приватном `toDto`. `Decimal` приводится к `number`.
- **Валидация входа**: DTO с `class-validator`; глобальный `ValidationPipe({ whitelist: true, transform: true })` не обходится. `UpdateDto` — через `PartialType`. Path-параметры `:id` — `ParseUUIDPipe`.
- **Ошибки** — стандартные Nest-исключения (`NotFoundException`, `ConflictException`, `UnauthorizedException`), а не голые throw/500.
- **Пароли** — `bcrypt` (10 раундов), хеш никогда не возвращается наружу.
- **Контракт ответов** не сломан: `/auth/*` → `{ accessToken, user }`; `GET /transactions` → `{ items, summary }`; `DELETE` → 204.
- **Prisma-схема**: уникальные индексы и каскады на месте (напр. `Category @@unique([userId, name])`), нужные индексы по `userId`/`date` не потеряны.

## Frontend (Next.js 16 + FSD)

- **FSD: импорты только вниз** `app → views → widgets → features → entities → shared`. Нет импортов из равного/вышестоящего слоя.
- **`src/app/` — только роутинг**: тонкие `page.tsx`/`layout.tsx`, бизнес-логика в `features`/`entities`, страница рендерит соответствующий `views/*`.
- **Структура feature-слайса**: `api/` (вызовы бэка), `model/` (стор, хуки, zod-схемы), `ui/` (компоненты).
- **API только через `shared/api/http.ts`** (`api.get`/`api.post`): относительные пути `/api/*`, никаких абсолютных URL и ручного `fetch` в компонентах. Токен подставляет сам http-слой.
- **Auth-состояние** — Zustand store (`features/auth/model/store.ts`, persist, ключ `auth`). Логика, зависящая от auth, ждёт `_hasHydrated` перед проверкой `isAuthenticated` (иначе ложный редирект на первом рендере).
- **Защищённые роуты** в группе `(protected)`, публичные — в `(auth)`.
- **Формы**: react-hook-form + zod, схемы в `features/<name>/model/schemas.ts`, тип через `z.infer`, UI поверх `shared/ui/form.tsx`.
- **UI**: shadcn-компоненты добавляются `npx shadcn@latest add` и живут в `shared/ui/`; классы мёржатся через `cn()`; тосты — `sonner`. Не плодить кастомные дубликаты существующих shadcn-компонентов.
- **Серверные секреты не утекают в клиент**; `"use client"` ставится осознанно, а не «на всякий случай».

## Стиль

- **TypeScript strict** на обоих воркспейсах: без `any` (где неизбежно — `unknown` + сужение), без `@ts-ignore` без комментария-обоснования, без неявных `any` в сигнатурах.
- **Именование**: компоненты/классы — `PascalCase`; переменные, функции, хуки — `camelCase` (хуки с префикса `use`); файлы фронта по FSD-конвенции (`*.api.ts`, `*.schemas.ts`, `use-*.ts`); файлы бэка — `<module>.<role>.ts` (`*.controller.ts`, `*.service.ts`, `*.command.ts`, `*.handler.ts`).
- **Бэкенд-конвенции** соблюдены: `target ES2021`, `module commonjs`; доменные/входные DTO разнесены (`domain/` vs `dto/`); маппинг наружу — приватный `toDto`.
- **Импорты**: путь через алиасы (`@/*` на фронте), без длинных относительных `../../..`; группировка external → internal; не тянуть весь модуль ради одного хелпера.
- **Без магических значений** — константы выносятся (фронт: `shared/config`; общие литералы — именованные).
- **Форматирование отдаёт Prettier** — не спорим о кавычках/отступах/запятых в ревью; если есть дифф от `npm run format`, это блокер, а не повод для дискуссии.
- **Комментарии** — по делу (зачем, не что); код пишется в стиле окружающих файлов (плотность комментариев, идиомы, нейминг).
- **Тексты**: пользовательские сообщения/UI — единый язык проекта; технические идентификаторы остаются в оригинале.

## Пропускать при ревью

Не тратим время ревьюера и не блокируем PR на:

- **Форматирование, которое чинит Prettier** (кавычки, отступы, переносы, trailing comma) — это работа `npm run format`, а не комментарий в PR.
- **Субъективные стилевые придирки** при уже зелёном линте: личные предпочтения по структуре кода без нарушения конвенций проекта — максимум nit/необязательное предложение, не блокер.
- **Сгенерированное и вендорное**: `node_modules/`, `frontend/.next/`, `backend/dist/`, `*.lock`, вывод `prisma generate` — не ревьюим построчно (но проверяем, что они не закоммичены по ошибке).
- **shadcn-компоненты «как из коробки»** в `shared/ui/`, добавленные через `npx shadcn@latest add` без ручных правок — доверяем реестру, смотрим только кастомизации.
- **Применённые миграции Prisma** в `prisma/migrations/` построчно — проверяем намерение (что меняет схему) и наличие, а не SQL посимвольно.
- **Микро-оптимизации без замеров** — не требуем переписывать читаемый код ради гипотетической производительности на не-горячем пути.
- **Bikeshedding по неймингу** в разумных пределах: если имя понятное и в стиле проекта — не блокируем из-за вкусовщины.
- `package-lock.json` и другие lock-файлы.
- `*.log` файлы.

## Чек-лист ревьюера

- [ ] Заголовок и коммиты — Conventional Commits.
- [ ] Тело PR: Summary + Test plan, описание совпадает с диффом.
- [ ] `npm run lint` и type-check зелёные, Prettier без диффа.
- [ ] Нет секретов/мусора/отладки в дифе; новые env — в `.env.example`.
- [ ] Backend: скоупинг по `req.user.id`, JWT-guard, границы через CQRS, domain DTO наружу, миграция при изменении схемы.
- [ ] Frontend: импорты FSD вниз, API через `http.ts`, формы RHF+zod, учтена гидрация auth.
- [ ] Документация (`CLAUDE.md`) обновлена под новые конвенции.
- [ ] После merge ветка удалена (`git branch -d <branch> && git push origin --delete <branch>`).
