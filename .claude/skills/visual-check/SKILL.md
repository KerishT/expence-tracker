## Аргументы

```
/visual-check [url]
```

- `[url]` — конкретный URL для проверки, например `http://localhost:3000/dashboard`.
  Если не указан — проверяются все страницы приложения.

## Страницы приложения (по умолчанию)

```
http://localhost:3000/login
http://localhost:3000/register
http://localhost:3000/dashboard
http://localhost:3000/transactions
http://localhost:3000/categories
```

## Вьюпорты для проверки

| Режим   | Ширина | Высота | Описание            |
| ------- | ------ | ------ | ------------------- |
| Desktop | 1280   | 800    | Стандартный ноутбук |
| Mobile  | 375    | 812    | iPhone SE / 13 mini |

## Алгоритм выполнения

1. **Проверить доступность сервера**

   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
   ```

   Если сервер недоступен (код не 200/3xx) — сообщить пользователю:

   > "Фронтенд не запущен. Запустите: `npm run dev:frontend`"
   > И прервать выполнение.

2. **Определить список страниц**
   - Если аргумент передан → `PAGES = [аргумент]`
   - Если аргумент пустой → `PAGES = [все страницы из списка выше]`

3. **Для каждой страницы выполнить проверку:**

   **3а. Десктоп (1280×800)**
   - Установить вьюпорт через `browser_resize` (width: 1280, height: 800)
   - Открыть страницу через `browser_navigate`
   - Дождаться загрузки через `browser_wait_for` (селектор `body` или пауза 1500ms)
   - Сделать скриншот через `browser_take_screenshot`
   - Получить snapshot доступности через `browser_snapshot`
   - Зафиксировать наблюдения (горизонтальный скролл, overflow, поломанные блоки)

   **3б. Мобайл (375×812)**
   - Установить вьюпорт через `browser_resize` (width: 375, height: 812)
   - Обновить страницу через `browser_navigate` (тот же URL)
   - Дождаться загрузки
   - Сделать скриншот через `browser_take_screenshot`
   - Получить snapshot доступности через `browser_snapshot`
   - Зафиксировать наблюдения

4. **Закрыть браузер** через `browser_close`

5. **Сформировать итоговый отчёт** (формат ниже)

## Что проверять при анализе скриншотов и snapshot

- **Горизонтальный скролл** — контент выходит за границы экрана
- **Обрезанные/перекрытые элементы** — кнопки, заголовки, поля ввода
- **Сломанный grid/flex** — элементы расположены не в ряд/колонку как ожидается
- **Мелкий текст на мобайл** — менее 14px, нечитаемый
- **Кнопки слишком мелкие** — touch target меньше 44×44px
- **Навигация** — sidebar/меню корректно скрыто/адаптировано на мобайл
- **Формы** — поля ввода не выходят за пределы экрана
- **Изображения** — не растянуты, не обрезаны критично

## Формат отчёта

```
## Визуальная проверка вёрстки

### /login
**Desktop 1280×800:** ✅ Нет проблем
**Mobile 375×812:** ⚠️ Кнопка "Войти" имеет малый touch target (~32px высота)

### /dashboard
**Desktop 1280×800:** ✅ Нет проблем
**Mobile 375×812:** ✅ Нет проблем

---
**Итого:** проверено 5 страниц × 2 вьюпорта = 10 проверок
**Найдено проблем:** 1
```

## Правила

- Не изменять никакой код — только наблюдение и отчёт
- Для защищённых страниц (`/dashboard`, `/transactions`, `/categories`) приложение
  автоматически редиректит на `/login` если нет сессии — это нормальное поведение,
  фиксировать редирект в отчёте, но не считать ошибкой
- Если страница редиректнула — делать скриншот итогового состояния (страницы логина)
  и отмечать: "редирект на /login (ожидаемо)"
- Все наблюдения формулировать конкретно: что именно сломано, на каком вьюпорте
- Если явных проблем нет — писать ✅, не придумывать проблемы
